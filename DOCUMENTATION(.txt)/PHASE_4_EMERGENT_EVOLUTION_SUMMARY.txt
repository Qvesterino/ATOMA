EXECUTIVE SUMMARY
================================================================================

PHASE 4 implements EMERGENT NETWORK EVOLUTION — a behavioral adaptation layer
that allows networks to develop unique "personalities" over time based on their
history, WITHOUT creating new stats, feedback loops, or power progression.

CORE PRINCIPLE:
Two networks with identical stats should feel different because of their
history—not because one is stronger.

KEY ACHIEVEMENT:
Networks feel intelligent and alive, adapting their behavior based on learned
patterns. Completely transparent to mechanical balance.

================================================================================
WHAT "EVOLUTION" MEANS
================================================================================

Evolution influences ONLY:
  ✓ Priority weighting (which paths to choose)
  ✓ Path preference (routes through successful links)
  ✓ Timing bias (when to apply healing)
  ✓ Selection bias (which targets to prioritize)

Evolution does NOT influence:
  ✗ Strength/magnitude (healing amounts unchanged)
  ✗ Stats or caps (all unchanged)
  ✗ Feedback loops (none created)
  ✗ Visible progression (no UI, no bars)

================================================================================
THREE EVOLUTION AXES
================================================================================

AXIS 1: PATH PREFERENCE EVOLUTION
  What: Links that repeatedly block/heal successfully become preferred routes
  How: Track success history, bias cascade routing through proven paths
  Result: Healing feels "smarter" even though amounts unchanged
  Power: ZERO increase
  Stats: ZERO changed

AXIS 2: STRESS AVOIDANCE BIAS
  What: Network learns which regions are chronically corrupted
  How: Track corruption patterns, reduce priority for stressed areas
  Result: Healing distributes evenly instead of concentrating
  Power: ZERO increase
  Stats: ZERO changed

AXIS 3: RESONANCE STABILIZATION (Optional)
  What: Stable harmony zones maintain longer
  How: Track zone stability, prefer maintaining stable zones
  Result: Resonance feels more "persistent"
  Power: ZERO increase
  Stats: ZERO changed

DATA STRUCTURE (NOT A STAT)
================================================================================

Per-link metadata (NOT subject to stats rules):
  {
    blockSuccesses: 42,          // Counter (read-only)
    healSuccesses: 18,           // Counter (read-only)
    cascadeRoutings: 156,        // Counter (read-only)
    corruptions: 8,              // Counter (read-only)
    
    // Derived fresh each decision:
    successRate = blockSuccesses / corruptions
    preference = successRate × cascadeRoutings
    
    // Result:
    pathPreference: 1.15         // 15% more likely chosen
    stressAvoidance: 0.92        // 8% less likely if stressed
  }

CRITICAL DISTINCTION:
  These are metadata counters, NOT stats.
  They don't affect healing power, synergy, harmony, or any mechanical property.
  They're just preferences for routing decisions.

DESIGN PHILOSOPHY
================================================================================

EVOLUTION ≠ POWER PROGRESSION

Evolution (Phase 4):
  - Same network feels different over time
  - Stats unchanged
  - Power unchanged
  - New players can match veterans
  - Reset loses personality (expected)

Power Progression (NOT Phase 4):
  - Network gets stronger over time
  - Stats increase
  - Power increases
  - New players behind veterans (bad)
  - Reset loses power (very bad)

CORE PHILOSOPHY:
Phase 4 should make two networks with identical stats feel different
because of their history—not because one is stronger.
