Replace the dead `node.userData.personality.type` lookup with a **metric-derived personality resolver** that uses `MetricTierClassifier`:

```
Personality = f(synergy.tier, harmony.tier, stability.tier, corruption.tier)
```

| Personality | Trigger Condition | Concept |
|---|---|---|
| `CALM_ANALYST` | stability.high + harmony.mid+ | Stable, balanced → analytical calm |

| `ASCENDED_MYTHIC` | stability.high + harmony.high + synergy.high | Transcendent |

Fallback: If no condition matches → `CONVERGENCE_NEXUS`.

### Step 3: Replace hardcoded thresholds with MetricTierClassifier

**Remove:** The `config.metricThresholds` object (lines 113-119) in `_NodeMicroEvents.js`.

**Use instead:** Import `classifyMetricTier` and `getDefaultMetricThresholds` from `MetricTierClassifier.js`.

This gives us:
- Canonical thresholds (no drift)
- Hysteresis (prevents tier flickering)
- Consistent tier logic across all ATOMA systems

### Step 4: Emit `node.<metric>.<tier>` events on semantic bus

When a micro-event fires, emit canonical tier events:
- `node.corruption.high`
- `node.synergy.low`
- `node.stability.mid`
- etc.

Using `buildScopedMetricEventName('node', metric, tier)` from `MetricTierClassifier`.

### Step 5: Keep existing VFX and event types

No new VFX. All 10 personality event types stay. All metric-based events stay. All interaction events stay. Selection cascade stays.

Only change is **HOW personality is determined** and **HOW metric tiers are classified**.
