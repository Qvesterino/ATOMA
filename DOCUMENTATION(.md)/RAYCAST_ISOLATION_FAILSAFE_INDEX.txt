KEY CONCEPTS EXPLAINED
================================================================================

LAYERED PROTECTION:
  Layer 0 (Real Visuals) ← raycast = () => {}
  Layer 10 (Hit-Proxies) ← ONLY these raycasted
  
  Result: Real visuals never touched by raycaster

FOUR-PHASE SYSTEM:
  Phase 1: Architectural isolation (hit-proxy layer)
  Phase 2: Runtime violation detection (monitoring)
  Phase 3: Graceful failsafe degradation (survival)
  Phase 4: Dev-only invariant enforcement (assertions)

VIOLATION DETECTION:
  Monitors ALL raycaster.intersectObjects() calls
  Checks each object for violation markers
  Records violations with full audit trail
  Triggers failsafe on threshold breach (default: 2)

FAILSAFE MODE:
  Activated if violations detected
  Uses fallback selection (nearest-distance)
  No raycaster calls in failsafe
  Game continues without crash

SAFETY GUARANTEES:
  1. No raycast on real visuals (architecturally impossible)
  2. No geometry mutation (fresh geometries only)
  3. Deterministic selection (1:1 proxy ↔ node mapping)
  4. Engine survival (failsafe mode + fallback)

QUICK ANSWERS
================================================================================

Q: What problem does this solve?
A: Eliminates "Cannot assign to read only property 'boundingSphere'" crashes
   by preventing raycaster from ever touching real node geometries.

Q: How does it work?
A: Creates invisible hit-proxy spheres on layer 10, disables raycast on
   real visuals (layer 0), monitors for violations, and gracefully degrades
   if violations are detected.

Q: Is it safe?
A: YES. Four layers of protection + architectural isolation ensures
   crashes are structurally impossible.

Q: Will it affect performance?
A: Minimal. 0-5% FPS impact, same or faster than original raycasting.

Q: Can I disable it?
A: Not recommended, but all safety systems are independent. You'd need
   to modify main.js initialization.

Q: How do I test it?
A: Run: HitProxyDebug.stats() and RaycastFailsafeDebug.status()
   Both should show clean status (0 violations).

Q: What if it breaks?
A: Failsafe mode activates automatically. Fallback selection uses
   nearest-distance heuristic. Game continues.

Q: Can I monitor it?
A: YES. Use RaycastFailsafeDebug.violations() for violations and
   RaycastFailsafeDebug.auditTrail() for interaction history.

Q: Is it production-ready?
A: YES. Complete testing, documentation, debug API, and safety guarantees.
