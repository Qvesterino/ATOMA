================================================================================
WEEK 1 FORMULA
================================================================================

When visualMetrics available on both nodes:

  harmonyNorm = (nodeA.visual.harmonyNorm + nodeB.visual.harmonyNorm) / 2
  stabilityNorm = (nodeA.visual.stabilityNorm + nodeB.visual.stabilityNorm) / 2
  corruptionNorm = (nodeA.visual.corruptionNorm + nodeB.visual.corruptionNorm) / 2
  energyNorm = (nodeA.visual.energyNorm + nodeB.visual.energyNorm) / 2
  
  synergyNorm =
    (harmonyNorm × 0.40) +            // Harmony 40% (primary)
    (stabilityNorm × 0.30) +          // Stability 30%
    ((1 - corruptionNorm) × 0.20) +   // Anti-corruption 20%
    (energyNorm × 0.10)               // Energy 10%
  
  synergyNorm = clamp(synergyNorm, 0, 1)

RESULT: Clean, deterministic synergy value (0–1)

================================================================================
FORMULA COMPONENTS EXPLAINED
================================================================================

HARMONY (40%):
  - Most important factor for synergy
  - High harmony = good connection quality
  - From NodeDynamicMetrics.harmony

STABILITY (30%):
  - How stable are the nodes?
  - Stable nodes make better synergies
  - From NodeDynamicMetrics.stability

ANTI-CORRUPTION (20%):
  - Lower corruption = higher synergy
  - Chaotic/corrupted nodes hurt synergy
  - Computed as (1 - corruption)

ENERGY (10%):
  - Active nodes contribute modestly
  - Not the primary driver (only 10%)
  - From NodeDynamicMetrics.energyNorm

================================================================================
FALLBACK BEHAVIOR (WEEK 1)
================================================================================

If visualMetrics unavailable:
  → Falls back to ComputeSynergyScore2_0 (original)
  → synergyNorm = score (identical to 2.0)
  → visualIntegration = null

Result: Perfect backward compatibility. No breaking changes.

================================================================================
TROUBLESHOOTING
================================================================================

Q: synergyNorm always equals score?
A: VisualMetricModel not running. Check:
   1. VisualMetricModel_v1.js deployed
   2. visualMetrics.update(dt) in game loop
   3. node.userData.visualMetrics exists

Q: High performance overhead?
A: Check fallback percentage:
   - High fallback → visual metrics unavailable (not a problem)
   - Low fallback + high overhead → investigate visual calculation

Q: Inconsistent results?
A: Nodes with/without visualMetrics mixed. Ensure:
   1. All nodes have visualMetrics (game loop order)
   2. VisualMetricModel updates before synergy calc
   3. Enable debug: calc.setDebug(true)

Q: Values fluctuating?
A: If fluctuation small (<0.05 per frame), it's normal EMA smoothing
   If large fluctuation, check VisualMetricModel values are stable
