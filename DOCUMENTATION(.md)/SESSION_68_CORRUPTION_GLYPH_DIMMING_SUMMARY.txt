OVERVIEW
═══════════════════════════════════════════════════════════════════════════════

WHAT WAS BUILT
──────────────
A corruption-based glyph opacity reduction system that dims all node glyphs as
corruption increases. When corruption ≥ 0.65, glyphs progressively fade to 25%
opacity at corruption = 0.85.

WHY IT MATTERS
──────────────
Glyphs represent system state and meaning. As corruption degrades the system,
the symbols representing it should fade away. This creates a powerful visual
semantic: "System meaning becomes obscured as corruption dominates."

Complements existing corruption visual systems:
  - Corruption visual state (Session 66): Links/nodes deform physically
  - Corruption contagion (Session 67): Corruption spreads organically
  - NEW (Session 68): Glyphs dim to indicate meaning loss

═══════════════════════════════════════════════════════════════════════════════
CORE MECHANICS
═══════════════════════════════════════════════════════════════════════════════

OPACITY DIMMING
────────────────
- Stores base opacity on first frame per glyph child
- Each frame: final_opacity = base_opacity * dimming_factor
- Smooth linear fade from 100% to 25%

EMISSIVE REDUCTION
───────────────────
- Proportionally reduces emissive intensity
- Maintains visual consistency for glowing elements
- Creates coordinated "losing radiance" effect

DESATURATION
──────────────
- Applies progressive color shift toward grayscale (≥30% corruption progress)
- Up to 15% desaturation at max corruption
- Creates "system sickness" visual language
- Compound effect: opacity + desaturation = stronger visual impact

PRIORITY HANDLING
──────────────────
When both synergy reveal and corruption dimming are active:
  synergy_opacity = base_opacity + synergy_boost
  corrupted_opacity = synergy_opacity * dimming_factor
  
Result: Corruption overrides synergy. Visual metaphor: "Corruption silences meaning"

PUBLIC API
═══════════════════════════════════════════════════════════════════════════════

setCorruptionDimmingConfig(config)
─────────────────────────────────────
Customize dimming behavior at runtime.

Parameters:
  config.activeThreshold (0–1): Start dimming at this corruption level
  config.maxDimmingThreshold (0–1): Reach full dim at this level
  config.minOpacityFactor (0–1): Minimum opacity at max corruption

Example:
  glyphSystem.setCorruptionDimmingConfig({
    activeThreshold: 0.50,      // Start earlier
    maxDimmingThreshold: 0.75,  // Reach full dim sooner
    minOpacityFactor: 0.10      // Fade more aggressively
  });

getCorruptionDimmingConfig()
──────────────────────────────
Query current dimming configuration.

Returns:
  { activeThreshold, maxDimmingThreshold, minOpacityFactor }

getStatus()
────────────
Enhanced status reporting now includes:
  .corruptionDimmingConfig: { activeThreshold, maxDimmingThreshold, minOpacityFactor }

DESIGN DECISIONS
═══════════════════════════════════════════════════════════════════════════════

WHY 0.65 THRESHOLD?
────────────────────
- Matches corruption visual deformation threshold (Session 66)
- Ensures coordinated visual feedback: node glyphs dim + links deform
- Creates unified "system breakdown" signal at same corruption level

WHY 25% MINIMUM OPACITY?
──────────────────────────
- Glyphs remain faintly visible even at max corruption
- Suggests "system still existing but nearly dead"
- Prevents complete invisibility (visual continuity)
- Allows for future "recovery" animation from collapsed state

WHY OVERRIDE SYNERGY?
──────────────────────
- Corruption = system failure, more important than synergy state
- Semantic: When system breaks, meaning is lost (corruption > synergy)
- Visual priority: Corruption state should dominate UI

WHY DESATURATION?
──────────────────
- Enhances dimming effect with "sickness" visual language
- Synergy glyphs are vibrant/colorful (healthy state)
- Corrupted glyphs become gray/washed out (sick state)
- Compound effect stronger than opacity alone
