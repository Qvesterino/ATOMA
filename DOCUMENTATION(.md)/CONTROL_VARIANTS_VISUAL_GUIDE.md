# Control Node Variants - Visual Design Guide (Session 83)

## Category Overview
**Control Nodes** represent command authority, decision-making, and hierarchical control flow.
**All use COMMAND/DECISION TOPOLOGY** - the visual principle that authority flows through branching, hierarchical, and networked structures.

## NEW Session 83 Enhanced Variants

### Control 8: DecisionFork ⭐ NEW
```
Visual Structure:

Front View:                 Detail (split point):

    ╱╲╱╲                        ◆ (convergence core)
   ╱  ╲  ╲                     ╱│╲ (decision branches)
  │    │  │  (4 branches)     ─ ─ ─
  │    ◉  │  (central core)
   ╲  ╱  ╱
    ╲╱╲╱   (trunk from base)

Side View (showing taper):

  ━━━━  (thin branch tips)
  ════  (medium branch)
  ══════  (wide trunk)
  ═══════  (even wider at base)
```

**What Makes It Control?**
- Central trunk represents established authority
- Four branches represent decision paths
- Different taper rates (some bold, some fine)
- Convergence at central core
- Represents "decisions diverge from authority, then converge back"

**Visual Metaphor**:
- Multiple decision paths from central command
- Each path taper differently (consequences vary)
- All paths rejoin at decision core
- Red/magenta metallic finish for command authority

**Geometry Details**:
- Central trunk: octagonal cross-section, tapered upward
- 4 asymmetric branches: 6-point cross-section, different taper rates
- 16 segments per branch
- Central convergence octahedron core
- Zero primitives (all custom parametric tubes)
- Total ~3.5 KB geometry

**Design Inspiration**: Tree branches, decision trees, command fork points, neural pathways

### Control 9: AuthorityHelix ⭐ NEW
```
Visual Structure:

Front View:                    Side View:

   ▲ (narrow - tier 4)            ╱╲  (spiraling upward)
  ╱ ╲                            ╱  ╲
 ╱   ╲  (spiral tightens)       │    │
│     │                         │    │ (central axis)
│  ◯  │  (tier rings)           │    │
│     │                          ╲  ╱
 ╲   ╱  (radius decreases)        ╲╱
  ╲ ╱
   ▼ (wide - tier 1)

Top View:

    ╱──╲
   │  ◯  │  (spiral from above)
    ╲──╱
     ╱──╲
    │    │
     ╲──╱
```

**What Makes It Control?**
- Central axis represents chain of command
- Spiral strands represent authority flow
- Decreasing radius shows delegation downward
- Each tier distinct but connected
- Represents "command authority cascading through hierarchy"

**Visual Metaphor**:
- Authority spirals downward through ranks
- Tighter spiral = stronger authority concentration
- Tier rings show distinct hierarchical levels
- Red/magenta metallic for command flow

**Geometry Details**:
- 4 hierarchical tiers (radius: 0.5→0.2)
- 24 segments per tier (96 total)
- 3 full rotations (helix spiral)
- 5-point asymmetric cross-section per strand
- Central 8-sided authority axis
- Tier rings at key hierarchy points
- Total ~3.8 KB geometry

**Design Inspiration**: DNA helix, organizational hierarchy, spiral staircases, chain of command

### Control 10: CommandMatrix ⭐ NEW
```
Visual Structure:

Front View (cube view):           Network Layout:

    ◆─────◆─────◆                  ◆ (bright central node)
    │╱────│─────╲│                ╱│╲
    ◆─────●─────◆  (● = center)   ◆─●─◆
    │╲────│─────╱│                 ╲│╱
    ◆─────◆─────◆                  ◆

Side View (asymmetric):            Vector Flows:

    ◆ - - ◆               ◆ ─ ─ ─ ◆  (asymmetric ribbons)
    │     │              ╱         ╲
    ◆ ─ ● ─ ◆   (offset) ◆ ─ ┐ ─ ◆
    │     │               └ ─ ◆
    ◆ ─ ─ ◆
```

**What Makes It Control?**
- 3×3×3 lattice of command nodes
- Nodes at asymmetric positions (not perfect grid)
- Vector flows showing decision propagation
- Central bright node (unified command authority)
- Represents "distributed decisions flowing through network to unified core"

**Visual Metaphor**:
- Each node is a command decision point
- Asymmetric positioning shows independence
- Vector flows show command propagation
- Central node is convergence/unification point
- Red/magenta metallic for distributed authority

**Geometry Details**:
- 27 command nodes (3×3×3 grid)
- Octahedron nodes at lattice points
- Asymmetric node perturbation (+/- 0.08 offset)
- Asymmetric vector flows (ribbon-like connections)
- Central bright core (icosahedron)
- Selective connectivity (not all nodes connected)
- Total ~4.2 KB geometry

**Design Inspiration**: Network topology, distributed systems, lattice structures, organizational matrices

## Scene Integration

### Typical Control Node Placement
```
In 3D Network View:

    [Input] ──→ [Process] ──→ [Integration] ──→ [Analytics]
       │           │              │                   │
       └───────┬───┘              └────────┬──────────┘
               │                           │
            [Control] ◀─────[Storage]─────┘

Control nodes often:
- Make critical decisions about data flow
- Coordinate between different processing zones
- Override automatic behaviors
- Represent user commands/interventions
```

### Visual Recognition at Distance
```
All Control variants immediately recognizable by:
✓ Red/magenta color (vs cyan/amber/green/violet/silver)
✓ Command/decision topology (branching, hierarchical, networked)
✓ Asymmetric structure (complex, not simple)
✓ 3D volumetric form (not flat)
✓ Authority sense (central cohesion or radiating outward)
```
