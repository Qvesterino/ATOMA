═══════════════════════════════════════════════════════════════════════════════
CRITICAL FINDING: EXTREME SHAPES ARE COMPLETELY INVISIBLE
═══════════════════════════════════════════════════════════════════════════════

THE SITUATION:

1. EXTREME shapes are fully defined in _ExtremeAINodePack.js
   • 12 unique visual archetypes (Hyperbolic Prism, Singularity Knot, etc.)
   • Complete geometry creation methods exist
   • Visuals are production-quality

2. EXTREME nodes are spawned correctly
   • node.userData.isExtreme = true (set 15% of nodes)
   • node.userData.extremeArchetype = 0-11 (assigned correctly)
   • node.userData.extremeProfile created with metadata

3. BUT: EXTREME visuals are NEVER RENDERED
   • ExtremeAINodePack.applyArchetype() is NEVER called in rendering
   • Rendering pipeline does NOT check node.extremeArchetype
   • EXTREME nodes render as normal base shapes despite unique visuals existing

PROOF:
  • Searched: "applyArchetype" in codebase
  • Found: Only in _ExtremeAINodePack.js definition
  • Missing: Zero calls in main.js, rendering loop, or bootstrapping
  • Result: 12 unique visuals completely orphaned

IMPACT:
  • 15% of spawned nodes are EXTREME but visually identical to normal nodes
  • 12 unique visual archetypes exist but never appear in-game
  • Players cannot distinguish EXTREME nodes from normal nodes
  • EXTREME visual system is 100% inaccessible

═══════════════════════════════════════════════════════════════════════════════
SECONDARY FINDING: SPECIAL CATEGORIES HAVE NO VISUALS
═══════════════════════════════════════════════════════════════════════════════

THE SITUATION:

Six special node categories have colors defined but no geometry:
  • quantum (Indigo - 0x4400ff)
  • sigma (Bright Green - 0x00ff00)
  • emotional (Hot Pink - 0xff4488)
  • mythic (Gold - 0xffdd00)
  • prime (White - 0xffffff)
  • error (Red - 0xff3333)

WHAT HAPPENS:
  • Colors are in EnhancedNodeModels.getCategoryColor()
  • But NO switch cases in EnhancedNodeModels.create()
  • All fall through to default: return this.createInputNode()

RESULT:
  • All special category nodes render as INPUT nodes
  • Only the color differs (applied via material)
  • Intended visual distinction is completely lost
  • Players see generic cyan INPUT nodes, not special categories

═══════════════════════════════════════════════════════════════════════════════
ROOT CAUSE ANALYSIS: WHY EXTREME SHAPES ARE ORPHANED
═══════════════════════════════════════════════════════════════════════════════

DESIGN MISMATCH:

Layer 1 - Node Spawning (AINodes.js):
  • Correctly sets isExtreme and extremeArchetype flags
  • Attaches extremeProfile metadata
  • ✅ Working as intended

Layer 2 - Base Geometry Selection (EnhancedNodeModels.js):
  • Creates node geometry based on category (input, process, etc.)
  • Does NOT check for isExtreme flag
  • Does NOT check for extremeArchetype
  • ⚠️ Never branches to EXTREME visuals

Layer 3 - Rendering Pipeline (main.js, rendering loop):
  • Never calls ExtremeAINodePack.applyArchetype()
  • Never queries node.extremeArchetype
  • Never activates EXTREME visual layer
  • ✗ EXTREME shapes never rendered

MISSING LINK:
  Between Layer 1 (metadata set) and Layer 3 (rendering),
  no code exists to:
    1. Check if node.isExtreme === true
    2. Call ExtremeAINodePack.applyArchetype()
    3. Activate EXTREME visuals
