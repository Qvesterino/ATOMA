🎯 RULES IMPLEMENTED

  RULE 2: Visual Authority
    Each node has ONE primary owner (EnhancedNodeModels)
    Enhancement systems (evolution, ritual, aura) are SECONDARY
    Guards prevent duplicate persistent visuals

  RULE 3: Spawn Collision Safety
    Nodes spawning too close delay visual activation by 150ms
    Visual-only guard (no physics, no repositioning)
    Prevents overlapping auras and visual explosions

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

NEW METADATA FLAGS (on node.userData)

  visualOwner             → 'EnhancedNodeModels' (identifies primary owner)
  hasPrimaryVisual        → true (node has core geometry)
  visualReady             → true/false (can activate enhancement visuals?)
  visualActivationDelay   → 0-150+ ms (delay if spawning too close)
  spawnTime               → timestamp (when node was created)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

3 GUARD PATTERNS ADDED

  PATTERN 1: Early Return (Evolution VFX)
    if (!node.userData?.visualReady) return;
    Location: SafeEvolutionManager.updateGlow(), updateCore()

  PATTERN 2: Early Continue (Aura Loop)
    if (!aura.node?.userData?.visualReady) continue;
    Location: NodeAuraSystem_v1.update()

  PATTERN 3: Time-Based Check (Spawn)
    const elapsed = Date.now() - node.userData.spawnTime;
    if (elapsed < node.userData.visualActivationDelay) return false;
    Location: AINodes._checkVisualReadiness()

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

VISUAL ACTIVATION TIMELINE

  Scenario A: Single Node Spawn (Normal)
    ├─ createNode() called
    ├─ visualReady = true (no nearby nodes)
    ├─ Evolution guards don't trigger (visualReady = true)
    ├─ Aura guards don't trigger (visualReady = true)
    └─ All visuals activate immediately ✓

  Scenario B: Rapid Multi-Node Spawn (Collision)
    ├─ Node A: visualReady = true (first)
    ├─ Node B: visualReady = false (too close to A!)
    │  ├─ Evolution.updateGlow() → if (!visualReady) return [SKIP]
    │  ├─ Aura.update() → if (!visualReady) continue [SKIP]
    │  └─ After 150ms: _checkVisualReadiness() sets visualReady = true
    └─ Visuals activate cleanly without overlap ✓

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

OCCUPANCY & COLLISION DETECTION

  Occupancy Radius: 1.5 units (conservative, visual-only)
  
  Check Logic:
    nearby = nodes within 1.5 units of spawn position
    if (nearby.length > 0) {
      visualReady = false
      visualActivationDelay = 150 ms  ← Wait this long
    } else {
      visualReady = true
    }

  Result: No node-to-node visual overlap

VISUAL HIERARCHY (After Phase 2)

  Priority Order:
    1. CORE (EnhancedNodeModels) ← Always visible, primary
    2. EVOLUTION (SafeEvolutionManager) ← Secondary, waits for core
    3. AURA (NodeAuraSystem_v1) ← Tertiary, waits for both

  Guard Application:
    ├─ Core spawns immediately (no guard)
    ├─ Evolution checks if (visualReady) before spawning
    └─ Aura checks if (visualReady) before updating

  Result: No overlapping visuals, clear authority chain
