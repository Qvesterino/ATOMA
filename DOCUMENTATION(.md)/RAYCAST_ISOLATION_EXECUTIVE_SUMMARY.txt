THE CHALLENGE
================================================================================

PROBLEM:
Three.js periodically crashes with:
  "Cannot assign to read only property 'boundingSphere'"

ROOT CAUSE:
Raycaster accesses real node geometries at runtime, triggering
geometry.computeBoundingSphere() which mutates the bounding sphere property.

IMPACT:
- Unpredictable crashes during gameplay
- Lost player progress
- Poor user experience
- Cannot be fixed in Three.js (architectural limitation)

================================================================================
THE SOLUTION
================================================================================

APPROACH: Four-Layer Raycast Isolation & Failsafe System

Layer 1: ARCHITECTURAL SEPARATION
  ✓ Move raycasting from real visuals to invisible hit-proxies
  ✓ Real visuals on layer 0 (raycast disabled)
  ✓ Hit-proxies on layer 10 (ONLY these raycasted)
  ✓ Makes crashes structurally impossible

Layer 2: RUNTIME VIOLATION DETECTION
  ✓ Monitor all raycaster calls
  ✓ Detect any violations of isolation
  ✓ Record with full audit trail
  ✓ Provide visibility into system health

Layer 3: GRACEFUL FAILSAFE DEGRADATION
  ✓ If violations detected, activate failsafe
  ✓ Switch to fallback selection (nearest-distance)
  ✓ Game continues without crashes
  ✓ Ensures engine survival

Layer 4: DEVELOPMENT ASSERTIONS
  ✓ Dev-only invariant checking
  ✓ Catch edge cases in development
  ✓ Prevent issues before production
