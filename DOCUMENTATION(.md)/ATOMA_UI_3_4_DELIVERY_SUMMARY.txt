PROBLEM SOLVED
================================================================================

BEFORE 3.4 (Issues):
- Selection scattered across multiple systems (NodeLinking, AutoDetect, Tooltip)
- Hitbox/proximity detection auto-triggered panels
- NO single source of truth for selection state
- Conflicting selection sources caused confusion
- Unclear which system owned selection responsibility
- UI opened/closed based on unclear proximity/hover triggers
- Difficult to debug selection issues

AFTER 3.4 (Solution):
✓ Single SelectionCore3_4 is source of truth
✓ All systems query Core for selection state
✓ No more proximity-based or auto-detection selection
✓ Explicit LMB-based selection only
✓ Clear separation of concerns
✓ Observable pattern ensures UI stays in sync
✓ Easy to debug and extend

================================================================================
INTERACTION MODEL (SIMPLIFIED)
================================================================================

LMB ON NODE:
  ├─ No selection → SELECT node
  └─ Already selected → LINK + SELECT new

LMB ON EMPTY:
  ├─ DESELECT everything
  └─ CLOSE all UI

RMB ON SELECTED NODE:
  └─ CANCEL linking (selection stays)

RMB ON EMPTY:
  └─ CANCEL linking

E KEY (if selected):
  ├─ OPEN context menu
  └─ Options: Inspect, Focus, Link, Disconnect, Mark, Close

E KEY (if not selected):
  └─ NO EFFECT

ESC KEY:
  ├─ CLOSE all UI
  └─ DESELECT everything

CONTROL FLOW (UNIFIED)
================================================================================

Setup Sequence (NEW ORDER):
  1. setupSelectionCore()       ← FIRST: Create kernel
  2. setupSelectedNodeTopBar()  ← Create top bar
  3. setupNodeLinking2_1()      ← Replace old linking
  4. setupUIWiring3_4()         ← Wire all systems

On LMB Node:
  NodeLinking2_1._onLeftClick()
    → Get raycast node
    → If no selection: _selectNode()
    → If different: _attemptLink() + _selectNode()
    → Calls: selectionCore.selectNode(node)
    → Fires: onNodeSelected callback
    → UI systems update:
        * TopBar.show()
        * Badge.show()
        * Highlight.apply()
        * Label.apply()
        * Panel.show()

On LMB Empty:
  NodeLinking2_1._onLeftClick()
    → No raycast node
    → Calls: selectionCore.deselectNode()
    → Fires: onNodeDeselected callback
    → UI systems update:
        * TopBar.hide()
        * Badge.hide()
        * Highlight.remove()
        * Label.hide()
        * Panel.hide()
    → _closeAllUI()

On RMB:
  NodeLinking2_1._onRightClick()
    → Cancel linking mode
    → Selection STAYS (no deselect)

On E Key:
  NodeLinking2_1._setupEventListeners() → E handler
    → Check: if (selectionCore.hasSelection())
    → If yes: contextMenu.open()
    → If no: NO ACTION

On ESC Key:
  NodeLinking2_1._onEscapeKey()
    → _closeAllUI()
    → _deselectNode() (which calls selectionCore.deselectNode())

API REFERENCE
================================================================================

SelectionCore3_4:
  // Queries
  core.hasSelection()           // Boolean
  core.getSelected()            // Node or null
  core.getSelectedCode()        // String (QNT code)
  core.getSelectedCategory()    // String (category)
  core.isSelected(node)         // Boolean

  // Actions
  core.selectNode(node)         // Select
  core.deselectNode()           // Deselect
  core.toggleSelect(node)       // Toggle

  // Events
  core.onNodeSelected(callback)
  core.onNodeDeselected(callback)

UISelectedNodeTopBar3_4:
  // Display
  bar.show(node)                // Show with node info
  bar.hide()                    // Hide
  bar.update(deltaTime)         // Update (minimal)

  // Configuration
  bar.setSelectionCore(core)    // Set core reference

NodeLinking2_1:
  // Configuration
  linking.setSelectionCore(core)
  linking.setUIReferences(topBar, panel, menu, badge, highlight, label)

  // Control
  linking.update(deltaTime)
  linking.setEnabled(true/false)
  linking.dispose()
