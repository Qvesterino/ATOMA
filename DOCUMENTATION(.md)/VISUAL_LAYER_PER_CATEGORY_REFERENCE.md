## CATEGORY PROFILES

### INPUT

**Semantic**: Gateway / sensor / data source  
**Typical Role**: Network entry points  
**Visual Character**: Responsive, alert-oriented  

**Layer Access**:
- ✓ CORE_GEOMETRY: Immutable icosahedron
- ✓ SHELL_OUTLINE: Size by tier
- ✓ EDGE_GLOW: Clean edges
- ✓ AURA_LAYER: Receptive glow
- ✓ GLYPH_LAYER: Input symbol (arrow inward)
- ✓ STATE_GLYPH: Personality animation
- ✓ STRESS_INDICATOR: Overload particles (red)
- ✓ SELECTION_HIGHLIGHT: Standard wireframe
- ✓ FOCUS_RING: Standard ring
- ✓ DEBUG_OVERLAY: Dev tools

**Restrictions**: None (all standard rules apply)

**Common State Glyphs**:
- Curious: Orbiting dots (sampling behavior)
- Analytical: Spinning symbol (processing input)
- Aggressive: Fast pulse (urgent data)

## FUTURE PER-CATEGORY RESTRICTIONS

### Potential Future Additions (Not Yet Active)

These restrictions are NOT currently enforced but may be added:

#### Emotional Node Restrictions (EXAMPLE)
```
Emotional nodes might be restricted from:
- EDGE_GLOW (too mechanical-looking for emotional nodes)
- Strategic override: Must use expressive colors instead

Result: Edge glow disabled; aura opacity increased to compensate
```

#### Quantum Node Restrictions (EXAMPLE)
```
Quantum nodes might require:
- STATE_GLYPH always active (for superposition clarity)
- Dual-color rendering in CORE_GEOMETRY
- Enhanced GLYPH_LAYER complexity

Result: More visual indicators for uncertainty principle
```

#### Error Node Restrictions (EXAMPLE)
```
Error nodes might enforce:
- STRESS_INDICATOR opacity minimum 0.5 (always visible)
- RED color palette for AURA_LAYER
- Damage_Indicator layer (future) always active

Result: Clear visual warning of node failure
```

### How to Add Future Restrictions

1. **Document** the restriction here (with rationale)
2. **Update** per-category allow matrix
3. **Implement** enforcement in VisualOverlayAuditSystem
4. **Register** new rules with VisualLayerDebugger
5. **Deploy** with zero breaking changes to existing nodes

### Quick Category Lookup

```javascript
// Check what layers are active on INPUT node
const node = aiNodes.nodes.find(n => n.userData.category === 'input');
const layers = visualOverlayAudit.getNodeOverlays(node);
console.table(layers.overlays);

// Check all analytical nodes
const analyticalNodes = aiNodes.nodes.filter(n => 
  n.userData.category === 'analytics'
);
analyticalNodes.forEach(n => {
  const layers = visualOverlayAudit.getNodeOverlays(n);
  console.log(`Node ${n.userData.index}:`, layers.overlays.length, 'layers');
});

// Verify category compliance
visualOverlayAudit.scanAllNodes().violations.forEach(v => {
  console.warn(`${v.nodeId} VIOLATION: ${v.issue}`);
```
