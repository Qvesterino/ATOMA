TECHNICAL SCOPE
═════════════════════════════════════════════════════════════════════════════

CONTAGION ACTIVATION:
  • Threshold: Node corruption >= 0.60 (spread threshold)
  • Spreads to: Connected nodes with lower corruption
  • Direction: Unilateral (higher→lower) or bidirectional (mutual)
  • Mode: Always active, automatic, continuous

SPREAD MECHANICS:
  ✓ Base spread rate: 0.15 corruption/second
  ✓ Differential-based: Exponential curve (steeper gap = faster)
  ✓ Resistance factors: Per-link (0.1-10.0) and per-node (0.1-10.0)
  ✓ Proximity boost: Multiple sources accelerate spread (1.15x-1.5x)
  ✓ Saturation damping: Slows when differential < 0.1

SPREAD FORMULA:
  baseSpread = 0.15 × deltaTime
  intensity = (source - target)^1.5
  spread = baseSpread × intensity × (1/linkResistance) × (1/nodeImmunity)
  
  if (differential < 0.1):
    spread × saturationDamping(differential)

VISUALIZATION:
  ✓ Infected links glow red/orange (HSL 0.05)
  ✓ Pulsing emissive 2-8 Hz (speed = spread intensity)
  ✓ Base color preserved, overlay applied
  ✓ Visual language: "This link is transmitting corruption"

IMPLEMENTATION SUMMARY
════════════════════════════════════════════════════════════════════════════

ENTRY POINT:
  update(deltaTime, time) in NodeLinkingSystem
  └─ Calls _updateCorruptionContagion(deltaTime) every frame
  └─ Processed after synergy/harmony, before visual updates

ACTIVATION FLOW:
  1. Per-frame: _updateCorruptionContagion() scans all links
  2. For each link:
     a) Get source/target corruption levels
     b) Check if >= 0.60 (spread threshold)
     c) Determine spread direction(s)
  3. Calculate spread amount:
     a) Base rate × differential^1.5
     b) Apply link/node resistance
     c) Apply saturation damping
  4. Update target node corruption level
  5. Apply proximity boost if multiple sources
  6. Update visual feedback (red/orange glow)

CONTAGION STATE TRACKING:
  Link state:
    userData.contagionState = {
      isInfected: boolean,
      infectionIntensity: number,
      spreadDirection: string
    }
  
  Node state:
    userData.contagionLevel: number
    userData.contagionResistance: number
    userData.contagionBoost: number (multi-source)

KEY FEATURES
═════════════════════════════════════════════════════════════════════════════

1. EXPONENTIAL DIFFERENTIAL MODEL
   ├─ Larger corruption gap → faster spread
   ├─ Curve: (source - target)^1.5 (not linear)
   ├─ Result: Natural cascade dynamics
   └─ Physics: Pressure differential drives infection

2. MULTI-VECTOR BOOST
   ├─ 2 sources: 1.15x faster
   ├─ 3 sources: 1.30x faster
   ├─ 4+ sources: 1.45x-1.5x faster
   └─ Model: Overwhelmed defenses

3. RESISTANCE MECHANICS
   ├─ Per-link resistance (default 0.8 = 20% slower)
   ├─ Per-node immunity (default 1.0 = normal)
   ├─ Range: 0.1 (vulnerable) to 10.0 (resistant)
   └─ Application: All spread modified by both factors

4. SATURATION CONTROL
   ├─ When differential < 0.1: Apply damping
   ├─ Prevents overshoot and instability
   ├─ Nodes approach equilibrium smoothly
   └─ Behavioral: Natural infection plateau

5. BIDIRECTIONAL SPREAD
   ├─ When both nodes >= 0.60
   ├─ Spread flows both directions simultaneously
   ├─ Each side independent calculation
   └─ Result: Network-wide simultaneous escalation

6. VISUAL FEEDBACK
   ├─ Red/orange glow on infected links
   ├─ Pulse speed: 2-8 Hz (faster = higher spread)
   ├─ Intensity: 0.2-0.8 based on contagion activity
   └─ Immediate visual language: "Spreading now"

  ```javascript
  }
  ```

Example 3: Customize Link Resistance
  ```javascript
  // Make this link very resistant

  ```

Example 4: Boost Node Immunity
  ```javascript

  linkingSystem.setNodeContagionResistance(criticalNode, 5.0);  // 5x resistant
  ```

  ```javascript
  const activeContagions = linkingSystem.links
  ```
