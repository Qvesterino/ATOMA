CONFLICT RESOLUTION EXAMPLE — TWO LAYERS COMPETE
═══════════════════════════════════════════════════════════════════════════════

Scenario: Node is SELECTED + HIGH CORRUPTION

    BEFORE CONFLICT:
        [2] SELECTION_HIGHLIGHT wants: Bright wireframe glow
        [4] STRESS_INDICATOR wants:   Red particle burst

    PRIORITY CHECK:
        Selection = Priority 3
        Stress    = Priority 4
        → Selection wins (lower number = higher priority)

    RESOLUTION:
        ✓ Selection highlight renders at full opacity (0.4-0.75)
        ✓ Stress particle burst renders BEHIND selection
        ✓ Particles tinted to show corruption, but selection visible
        ✓ Core geometry never occluded

    RESULT:
        Player sees: Selection + Corruption emphasized together
        Core is:     Clearly readable

LAYER OPACITY BUDGET (CUMULATIVE)
═══════════════════════════════════════════════════════════════════════════════

When multiple layers render simultaneously, total opacity budget:

Layer Stack Scenario: All layers active on one node

    [8] SHELL_OUTLINE      opacity = 1.0   ← Fully opaque
    [7] AURA_LAYER         opacity = 0.4   ← 40% intensity
    [6] GLYPH_LAYER        opacity = 0.5   ← 50% intensity
    [5] STATE_GLYPH        opacity = 0.3   ← 30% intensity
    ────────────────────────────────────────
    Result: Blended appearance, core still visible

Core readability equation:
    visibility = 1.0 - (0.4 × 0.5 × 0.3)  [approximate alpha blending]
                = ~0.94 (94% of core visible)
    
    ✓ SAFE (core clearly readable)


Worst-case violation scenario (BLOCKED):

    [7] AURA_LAYER         opacity = 0.9   ← TOO HIGH
    [6] GLYPH_LAYER        opacity = 0.9   ← TOO HIGH
    [5] STATE_GLYPH        opacity = 0.9   ← TOO HIGH
    ────────────────────────────────────────
    Result: visibility ≈ 0.27 (core nearly hidden)
    
    ❌ REJECTED by audit (Rule 2 violation)

RENDER ORDER (THREE.JS renderOrder PROPERTY)
═══════════════════════════════════════════════════════════════════════════════

Three.js renders HIGHER renderOrder values ON TOP:

    renderOrder = 1000  ← CORE_GEOMETRY (absolutely top)
    renderOrder = 999   ← SHELL_OUTLINE
    renderOrder = 100   ← EDGE_GLOW
    renderOrder = 50    ← AURA_LAYER
    renderOrder = 40    ← GLYPH_LAYER
    renderOrder = 30    ← STATE_GLYPH
    renderOrder = 20    ← STRESS_INDICATOR
    renderOrder = 10    ← FOCUS_RING
    renderOrder = 5     ← SELECTION_HIGHLIGHT
    renderOrder = 0     ← DEBUG_OVERLAY (bottom)

Core uses HIGH renderOrder to guarantee it renders last (on top).

QUICK REFERENCE: IS MY VISUAL ALLOWED?
═══════════════════════════════════════════════════════════════════════════════

Step 1: What am I rendering?
        ↓
        • Filled plane/disc?     → ❌ STOP (Rule 1)
        • Wireframe outline?     → ✓ Continue
        • Low-opacity glow?      → ✓ Continue

Step 2: Does it cover the core?
        ↓
        • Yes, completely?       → ❌ STOP (Rule 2)
        • Yes, partially?        → Check opacity
        • No?                    → ✓ Continue

Step 3: What's my opacity?
        ↓
        • > 0.5 AND filled?      → ❌ STOP (Rule 1)
        • > 0.9 AND covers?      → ❌ STOP (Rule 2)
        • > 0.7 AND glyph?       → ❌ STOP (Rule 8)
        • Otherwise?             → ✓ ALLOWED

Step 4: Am I changing node size?
        ↓
        • Yes?                   → ❌ STOP (Rule 3)
        • No?                    → ✓ ALLOWED
