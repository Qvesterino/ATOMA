SESSION 54: CANONICAL BASE VISUAL STATE — EXECUTIVE SUMMARY
================================================================================

PROBLEM
─────────────────────────────────────────────────────────────────────────────
ATOMA nodes look correct BEFORE linking, but degrade after linking:
✗ Color shifts / changes
✗ Opacity collapses
✗ Core becomes flattened
✗ Aura dominates instead of framing
✗ Overall proxy-like appearance

ROOT CAUSE
─────────────────────────────────────────────────────────────────────────────
NodeVisualStateBinder v1.0 applied a LINKED visual preset that OVERRODE:
  - Core materials (color, emissive)
  - Core opacity (1.0 → 0.5)
  - Core renderOrder
  - Aura constraints

This preset was meant for temporary feedback, not final visuals.

SOLUTION
─────────────────────────────────────────────────────────────────────────────
Implemented CANONICAL BASE VISUAL STATE system v2.0

Core Philosophy:
  "Linking is a RELATIONSHIP, not a visual MUTATION."

Three Pillars:
  1. Capture base state on spawn (immutable, persistent)
  2. Restore base state before adding FX (undo mutations)
  3. Add link FX as separate mesh (doesn't touch core)

Result:
  ✅ Nodes look IDENTICAL before and after linking
  ✅ Only new element: subtle link arc FX
  ✅ No color shift, no opacity collapse, no degradation
  ✅ Glyphs unchanged, aura isolated (≤ 0.06 opacity)

VISUAL PRIORITY (STRICT, NO EXCEPTIONS)
─────────────────────────────────────────────────────────────────────────────
-1    AURA           (behind everything)
 0    CORE           (primary node mesh) ← MUST NOT CHANGE
10    GLYPHS         (symbols, icons)
50    LINK_FX        (arcs, glows)      ← NEW: link feedback
200   DEBUG          (debug overlays only)

THE RULE
─────────────────────────────────────────────────────────────────────────────
ON LINK:
  1. Restore base visual state (undo any mutations)
  2. Ensure core is opaque + correct renderOrder
  3. Add link FX as separate mesh (doesn't modify core)
  4. Verify no base state violations
  
RESULT:
  - Node looks IDENTICAL to before linking
  - Only new visual element: link arc (subtle feedback)
  - Core material NEVER mutated
  - Aura ALWAYS constrained (opacity ≤ 0.06)
  - Visual priority STRICT

USAGE
─────────────────────────────────────────────────────────────────────────────
Quick Start:

// On node spawn
captureBaseVisualState(node);

// On link event
restoreBaseVisualState(sourceNode);
restoreBaseVisualState(targetNode);
applyLinkFXOnly(sourceNode);

// OR: Use manager (handles both)
const binder = new NodeVisualStateBinder({ assertMode: true });
binder.registerNode(node);           // Captures base
binder.onNodeStateChange(node, 'LINKED');  // Restores + adds FX

KEY INSIGHTS
─────────────────────────────────────────────────────────────────────────────
1. Immutable Base State
   Once captured, base state is locked (Object.defineProperty, writable: false)

2. Restoration Pattern
   Always restore BEFORE adding new visual elements
   Prevents mutations from accumulating

3. Visual Priority Strict
   renderOrder is law: AURA=-1, CORE=0, LINK_FX=50
   No exceptions, no mutations, enforced

4. Linking ≠ Visual Change
   Linking adds a RELATIONSHIP, not a visual MUTATION
   Node looks the same, relationship is new

5. Assertions Catch Violations
   Enable assertMode: true in dev
   Catches any mutation immediately
