FOUR CORE GUARANTEES

1. ✅ NO LIVE SCENE REFERENCES
   
   Effects store ONLY:
   • Mesh (for direct mutation only, not positional data)
   • Cloned Vector3 snapshots
   • Scalar values (duration, scale, opacity)
   
   Effects NEVER store:
   ❌ node.position (live reference)
   ❌ mesh.userData (live reference)
   ❌ Any Three.js Object3D reference except mesh
   
   Result: Even if node despawns, link effects continue unaffected
           because they use CAPTURED positions, not live references


2. ✅ INPUT VALIDATION (NO SILENT FAILURES)
   
   All inputs validated BEFORE effect creation:
   • Missing required fields → REJECTED (null returned)
   • Invalid field types → REJECTED (null returned)
   • Reason logged to console
   
   Example validation flow:
   orchestrator.addPooled('linkPulse', { pulse: null })
   ├─ Validation: Missing pulse mesh? YES
   ├─ Result: null returned
   └─ Console: "[EffectPool] REJECTED: linkPulse - Missing pulse mesh"
   
   Result: No invalid effects created. All rejections logged.


3. ✅ SELF-TERMINATING ON CORRUPTION
   
   If effect state becomes invalid during update:
   • effect.corrupted = true
   • Next frame: Auto-removed (not crashed)
   • Console: Logged as diagnostic
   
   Example:
   effect.update() throws error:
   ├─ Catch exception
   ├─ Set effect.corrupted = true
   ├─ Log error to console
   └─ Next tick: effect removed gracefully
   
   Result: No runtime crashes from invalid effects


4. ✅ DETERMINISTIC POOLING LIFECYCLE
   
   Acquisition → Reset → Initialize → Use → Complete → Pool
   
   ┌─────────────────────────────────────────┐
   │ 1. Acquire from pool                    │
   │    ├─ Pop effect from type pool         │
   │    └─ If empty: create new              │
   │                                         │
   │ 2. Reset completely                     │
   │    ├─ Clear all fields                  │
   │    ├─ No state leakage                  │
   │    └─ Function refs kept (generic)      │
   │                                         │
   │ 3. Initialize with snapshots            │
   │    ├─ Clone all vectors                 │
   │    ├─ Bind update() function            │
   │    └─ Ready to use                      │
   │                                         │
   │ 4. Use (multiple frames)                │
   │    ├─ Update accumulates deltaTime      │
   │    ├─ Never reads live scene            │
   │    └─ Calls update() every frame        │
   │                                         │
   │ 5. Complete                             │
   │    ├─ Call dispose()                    │
   │    ├─ Return to pool                    │
   │    └─ Orchestrator removes from list    │
   └─────────────────────────────────────────┘

EFFECT_INPUT_INVARIANT

Non-Negotiable Rule:
"No effect update may read data from live scene graph objects."

Why this matters:
• Rare nodes can despawn while link effects are running
• Without invariant: effect tries to read node.position → crash
• With invariant: effect uses snapshot → safe even if node gone

How it's enforced:
1. All positions cloned at creation (snapshot)
2. Update() NEVER accesses live node/mesh
3. Verification method provided: verifyEffectInputInvariant()
4. Violations logged to console (no throw)

EXAMPLE: FIXING RARE NODE HOLOGRAM LOSS

PROBLEM:
  Link pulse creates effect with nodeReference
  Rare node despawns (unlink)
  Link pulse still running, tries to read node.position
  → node is null → crash or glitch

SOLUTION:
  Link pulse creates effect with positionSnapshot
  addPooled('linkPulse', {
    startPos: sourceNode.position.clone(),    // ✅ SNAPSHOT
    endPos: targetNode.position.clone(),      // ✅ SNAPSHOT
  })
  
  During update:
  ✅ Uses cloned positions (immutable)
  ✅ Never reads sourceNode.position
  ✅ Never reads targetNode.position
  ✅ Safe even if nodes despawn
  
Result: Rare nodes retain hologram throughout linking lifecycle
