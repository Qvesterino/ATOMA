Node Identity Authority Static Audit
**1️⃣ Identity Systems Inventory (where identities are read/set)**  
- `node.uuid` (THREE auto-generated, regenerated every spawn/rebuild).  
- `userData.id` (custom, sometimes same as nodeId, sometimes absent).  
- `userData.nodeId` (custom; often set by spawn wrappers / hit-proxy).  
- `userData.index` (array position; unstable across rebuild).  
- `hashNodePosition(pos)` (SemanticGlyphAI fallback; non-deterministic if nodes move).  
- `"node-${index}"` (GlyphLayer4 fallback when uuid missing).  
- `fusionRegistry` keys (GlyphLayer4_MultiFusion: `node.uuid || "node-"+index`).  
- `semanticState` keys (SemanticGlyphAI: `userData.index ?? hashNodePosition`).  
- `HitProxySystem` registry keys (uses `targetNodeId` passed in from spawn/registrar; typically userData.id/nodeId).  
- Spawn-related utilities: `UniqueSpawnService`, `SpawnAuthority`, `NodeRegistry` (assign/track nodeId; seen in spawn pipeline docs/patch wrappers).

**2️⃣ Subsystem Identity Map**  
| Subsystem | Identity Used | Why | Stable? | Deterministic? |
|-----------|---------------|-----|---------|----------------|
| GlyphLayer4_MultiFusion | `node.uuid` (fallback `node-${index}`) | Created at fusion registration | No (uuid regenerates per rebuild) | Yes per session |
| SemanticGlyphAI (state & fusion lookup) | `userData.index` else `hashNodePosition` | Computes nodeId each frame | No (index/order changes; hash changes if node moves) | Hash nondeterministic with motion |
| HitProxySystem / AutoRegistrar | `targetNodeId` stored on proxy (from userData.id/nodeId) | Map proxy→node | Yes if userData.id stable | Yes if assigned once |
| NodeLinkingSystem (selection/crosshair) | Uses node refs from hit-proxy resolved by `targetNodeId` | Interaction ownership | Depends on `targetNodeId` stability | Yes if source stable |
| Metrics/AI (e.g., AdaptiveGlyphRendering) | Reads `userData.*` metrics keyed by node object | Uses node reference, not key | N/A | N/A |
| SpawnAuthority / UniqueSpawnService | Assigns `userData.nodeId` / `userData.id` | Ensure uniqueness across spawns | Yes if persisted | Yes (if deterministic generator) |
| Fusion helpers (helper meshes) | Use same nodeId as SemanticGlyphAI (state map) | State lookup | No (see above) | No if hash |

**3️⃣ Fusion Registry Key Authority (set vs get)**  
- Set: `_GlyphLayer4_MultiFusion.createGlyphFusion` → `const nodeId = node.uuid || "node-"+index; fusionRegistry.set(nodeId, fusionData);`  
- Get: `SemanticGlyphAI.applySemanticVisualsToNode` → `fusion = glyphLayer4.fusionRegistry.get(nodeId);` where `nodeId` = `userData.index ?? hashNodePosition(position)`.  
- Mismatch: uuid vs index/hash → fusionRegistry.get returns undefined ⇒ helpers/visuals skip.

**4️⃣ SemanticGlyphAI NodeId Derivation (exact)**  
`const nodeId = node.userData.index !== undefined ? node.userData.index : this.hashNodePosition(node.position);`

**5️⃣ Spawn System Identity (observed patterns)**  
- HitProxyAutoRegistrar sets `proxy.userData.targetNodeId = node.userData.id || node.userData.nodeId || node.uuid`.  
- SpawnAuthority/UniqueSpawnService (not shown setting fields in this excerpt) typically assign `userData.nodeId` (int/string) meant to persist; intended canonical.  
- `node.uuid` regenerated on every THREE.Mesh creation (rebuild → new uuids).  
- `userData.index` comes from array order; recomputed after rebuild.

**6️⃣ Drift Detection (set/get mismatches)**  
- GlyphLayer4 uses uuid; SemanticGlyphAI uses index/hash → drift.  
- HitProxy uses userData.id/nodeId; SemanticGlyphAI ignores those → drift between hover selection (proxy → node) and glyph visuals.  
- Any rebuild regenerates uuid and reshuffles index; fusion keys and semantic keys diverge.

**7️⃣ Canonical Identity Recommendation (based on stability & cross-system compatibility)**  
- Prefer a single, explicit, persistent field: `userData.nodeId` (or `userData.id` if already canonicalized) assigned once at spawn and reused everywhere.  
- Rationale: survives world rebuild if reloaded from data; deterministic if generated by SpawnAuthority; already used by hit-proxy pipeline.  
- All subsystems (GlyphLayer4, SemanticGlyphAI, HitProxySystem, LinkingSystem) should converge on `userData.nodeId` for set/get keys to eliminate fusion/hover drift.

**Summary**  
Identity drift stems from three competing schemes: uuid (fusion set), index/hash (semantic state/get), and nodeId/id (hit-proxy & spawn). Canonicalize on a persistent `userData.nodeId` to align fusion lookups, semantic state, and interaction.
