## Implementované optimalizácie

### ✅ Item #4: Nahradenie clone() za scratch vectors

**Popis:** Eliminácia per-frame alokácií Vector3 a Color objektov v hot update loope.

**Implementácia:**
1. Pridané 5 nových scratch vectors v konštruktore:
   - `_scratchVecA` - pre kalkulácie pozícií
   - `_scratchVecB` - pre kalkulácie pozícií
   - `_scratchVecC` - pre linkDir, surfaceDir, atď.
   - `_scratchVecD` - pre dockOffset, spray origin, atď.
   - `_scratchColor` - pre color klonovanie

2. Nahradené ~15-20 per-frame `.clone()` volaní v hot update loope:
   - `linkDir.clone().normalize()` → `_scratchVecC.copy(linkDir).normalize()`
   - `sourceCenter.clone()` → `_scratchVecA.copy(sourceCenter)`
   - `targetCenter.clone()` → `_scratchVecB.copy(targetCenter)`
   - `dockPos.clone()` → `_scratchVecD.copy(end)`
   - `surfaceDir.clone().negate()` → `_scratchVecB.copy(surfaceDir).negate()`
   - `ringColor.clone()` → `_scratchColor.copy(ringColor)`
   - A ďalšie v dock ring a ghost ring sekcii

**Odhadovaný zisk:**
- Eliminácia ~15-20 alokácií na link za frame
- Zníženie GC pressure
- Merateľné zlepšenie pri 10+ linkoch

**Riziko:** Nízke — scratch vectors sú bezpečné na reuse v synchronnom kóde

### ✅ Item #2: Dock ring/spray → vlastný cadence (20Hz)

**Popis:** Dock efekty sú sekundárne vizuálne prvky, ktoré nepotrebujú 30Hz aktualizáciu.

**Implementácia:**
1. Pridaný nový cadence accumulator: `this._accDock`
2. Aktualizačná logika:
   ```javascript
   this._accDock += deltaTime;
   let runDock = this._accDock >= (1 / 20);
   if (runDock) this._accDock -= (1 / 20);
   ```
3. Dock ring, dock spray a dock ghost teraz bežia pri 20Hz:
   - Pôvodne: `if (heavyTick)` (30Hz)
   - Teraz: `if (runDock)` (20Hz)

**Opravená chyba:** Source injection ostáva pri 30Hz (heavyTick) — bol omylom vnútri `runDock` bloku.

**Odhadovaný zisk:**
- ~33% menej dock update volaní (20Hz namiesto 30Hz)
- Úspora CPU času pre vzdialené linky s dock efektm

**Riziko:** Nízke — 20Hz je stále nad kritickým thresholdom pre hladký vizuálny dojem

### ✅ Item #3: Source injection → LOD gating

**Popis:** Source injection je výpočtovo náročný efekt, ktorý sa má preskočiť pre vzdialené linky.

**Implementácia:**
1. Pridaná LOD kontrola pred source injection update:
   ```javascript
   if (lodAllowsParticles) {  // lod < 2
       state.sourceInjection.update(visualTime, injectionAnchor, linkDir, injectionFlow);
       // ... burst logika
   }
   ```
2. `lodAllowsParticles` je už definované ako `lod < 2`

**Odhadovaný zisk:**
- Source injection sa preskočí pre všetky LOD 2+ linky
- Významná úspora GPU výkonu pre veľké siete s množstvom vzdialených liniek

**Riziko:** Nízke — LOD 2+ linky sú dostatočne vzdialené, aby straty neboli viditeľné

### ⏸️ Item #1: Deduplikácia uniform writes — uTime zdieľaný (odložený do Phase 2)

**Dôvod na odloženie:**
- Každý strand má vlastný materiálnu inštanciu — žiadne zdieľanie v rámci jedného linku
- uTime sa píše na `visualTime`, ktorý sa mení každý frame — žiadne redundantné zápisy v rámci toho istého materiálu
- Skutočná deduplikácia vyžaduje:
  - Zdieľanie materiálov medzi linkmi alebo
  - Použitie `onBeforeRender` callbacku

**Plán pre Phase 2:**
1. Implementovať zdieľanie materiálov pre rovnaké kategórie liniek
2. Pridať sledovanie aktualizovaných materiálov v frame (WeakMap/Set)
3. Alebo presunúť uniform writes do `onBeforeRender` callbacku

**Odhadovaný zisk (Phase 2):**
- ~50-80% zníženie uniform writes ak materiály sú zdieľané
