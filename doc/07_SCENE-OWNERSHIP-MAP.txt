HIGH-RISK RUNTIME SCENE MUTATIONS
CRITICAL: NO ROOT GROUPS
Risk: Nodes and links are added directly to this.scene instead of organized root groups like nodesRoot, linksRoot, vfxRoot.

Impact:

No hierarchical organization
Difficult to batch-remove nodes or links
Performance impact on raycasting (no spatial optimization via group culling)
Cleanup complexity (must iterate entire scene)
Systems directly adding nodes/links:

AINodes.js - Adds nodes at runtime: this.scene.add(node)
NodeLinkingSystem.js - Adds link groups at runtime: this.scene.add(linkGroup)
NodeLinkingInvariantGuard.js - Repairs detached nodes: this.scene.add(node)
World.js - Adds decorative nodes (disabled): this.scene.add(node)
PER-FRAME SCENE MUTATIONS (LOW RISK)
Only 2 systems perform per-frame scene mutations, and both are cleanup operations:

EnvironmentalHazards.js - Removes hazard bolts: hazard.bolts.forEach(bolt => this.scene.remove(bolt.line))
main.js - Removes objects via parent: toRemove.forEach(obj => obj.parent?.remove(obj) || this.scene.remove(obj))
Assessment: These are safe cleanup operations, not problematic per-frame additions.

RUNTIME ADDITIONS (MEDIUM RISK)
Many systems add objects at runtime, but these are event-driven (not per-frame):

High-frequency additions:

Link visual creation - Every link adds a group (NodeLinkingSystem.js)
UI highlights - On selection (multiple UI systems)
VFX objects - On events (50+ VFX systems)
Hit proxies - On raycast target creation
Missing removal patterns:

Some systems have destroy() methods, but not all
Temporary objects (debug meshes, visual feedback) may leak
Memory trail systems appear to have proper cleanup
