# SYSTEM_MAP — ATOMA

This document provides a **high-level map of ATOMA's systems**
and how they relate to each other.

It is not an implementation reference.
It is a conceptual overview.

---

## 1. CORE STRUCTURE

ATOMA is built around a **network model**.

- Nodes = functional / cognitive units
- Links = relationships and flow
- The network is the primary interface

Everything else exists to support or influence this structure.

---

## 2. NODE SYSTEM

Nodes represent:
- capabilities
- processes
- states

Each node has:
- a category
- internal metrics
- behavioral state

Nodes do not act in isolation.
Their meaning emerges through connections.

---

## 3. LINK SYSTEM

Links represent:
- flow
- load
- stress
- influence

Links are where **pressure is felt**.

Visual and behavioral changes in links
are primary indicators of system state.

---

## 4. METRIC LAYER (ABSTRACT)

High-level systemic forces:

- Synergy → constructive interaction
- Harmony → global balance
- Corruption → overload, decay, misalignment

Metrics:
- influence behavior
- influence visuals
- influence future potential

Metrics are **not UI elements**.
They manifest through the system.

---

## 5. VISUAL EXPRESSION LAYER

Visuals do not mirror metrics directly.

Instead, they express:
- tension
- instability
- coherence
- decay

This layer translates invisible forces
into perceivable behavior.

---

## 6. PLAYER INTERACTION LAYER

The player:
- observes
- intervenes
- reconfigures

The system reacts over time,
not instantly.

Understanding emerges through interaction,
not instruction.

---

## 7. AI & META LAYER (DEVELOPMENT)

During development:
- ChatGPT defines architecture and intent
- Local AI executes scoped changes
- Review AI validates safety

These systems do not exist in the game world
but shape its evolution.

---

## FINAL NOTE

- This map is intentionally incomplete.
- ATOMA is designed to grow, but all growth must respect this structure.
- If a new system cannot be placed clearly within this map, it likely does not belong.
