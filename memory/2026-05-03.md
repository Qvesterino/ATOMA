- The long-standing node-local "double vertical torus + horizontal rings + pink orbiters" glitch was traced to `_EmergentThoughtStorms5_0.js`, not `GlyphLayer4_MultiFusion`.
- Runtime fingerprint for the storm package:
  - two overlapping `corruption` storms on the same `ERROR` node cluster
  - each storm contributes `12` storm glyphs using the repeating `['shard', 'shard', 'spiral']` pattern
  - two stacked storms therefore present as `16` tetrahedron-like shards + `8` torus orbit glyphs, plus halos/ripples/arcs

  - `shouldSpawnStorm()` allowed `corruption > threshold` even when `linkCount = 0`, `nodeCount = 1`, `thoughtDensity = 0`
  - `spawnStorm()` allowed duplicate active storms of the same type on the same cluster
- Surgical fix in `_EmergentThoughtStorms5_0.js`:
  - require actual network activity before any storm can spawn (`linkCount`, neighboring nodes, active chains, or thought density)
  - suppress duplicate active storms of the same type on the same cluster while one is already active

- Root causes in `GlyphFusionZone.js`:
  - `CONVERGENCE_THRESHOLD = 2` was too permissive, so ordinary 2-link pass-through nodes could synthesize the full composite/fusion package
  - active zones were only pruned by live link count, not by actual endpoint glyph presence, so fusion effects could linger after link topology changed
- Surgical fix in `GlyphFusionZone.js`:
  - raised `CONVERGENCE_THRESHOLD` and `SEPARATION_TRIGGER_THRESHOLD` to `3`
  - added `enabled` gating plus `enable()` / `disable({ clear })`
  - pruned active zones when a node no longer has enough endpoint glyphs, not just enough links
