# 2026-04-01

- `ResonanceCascadeVisualization_Session117B` was simplified to a clear link/metric contract:
  - subscribes to `link.created`
  - subscribes to `metric:loadPressureHigh`
  - `link.created` seeds the cascade
  - `metric:loadPressureHigh` boosts the latest active cascade, or spawns a pressure bloom if none exists
- Legacy `cascade.start` / `cascade.hop` / `cascade.end` listeners are no longer used by `ResonanceCascadeVisualization_Session117B`.
- `link.created` spawn in `ResonanceCascadeVisualization_Session117B` is now delayed by 0.5s and deduped with a 3.5s per-link cooldown to avoid instant spawn spikes.
- Added a normalized metrics phase layer in `NodeMetricEngine.js`:
  - emits `metric.phase.changed`
  - payload includes `metric`, `phase`, `previousPhase`, `value`, `nodeId`
  - phases are `low`, `normal`, `high`
  - existing threshold events like `metric:loadPressureHigh` remain for compatibility
- `WaveBurstRouter_v1.js` now consumes `metric.phase.changed` for node-level phase routing and keeps legacy threshold events only as compatibility/fallback inputs.
- `ResonanceRuptureVisualSystem_Session133.js` now consumes `metric.phase.changed` for `corruption`, `stability`, and `loadPressure` rupture pressure routing while keeping legacy threshold events as fallback.
- `LinkMicroImpulseAdapter_v1.js` now consumes `metric.phase.changed` as the preferred normalized link impulse signal, with legacy threshold events kept as fallback and deduped.
- `CascadeEventBridge_v1.js` now consumes `metric.phase.changed` as a normalized entry point for synergy/corruption high phases, while preserving the existing flowState write path.
