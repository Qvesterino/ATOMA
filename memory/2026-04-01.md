# 2026-04-01

- `ResonanceCascadeVisualization_Session117B` was simplified to a clear link/metric contract:
  - subscribes to `link.created`
  - subscribes to `metric:loadPressureHigh`
  - `link.created` seeds the cascade
  - `metric:loadPressureHigh` boosts the latest active cascade, or spawns a pressure bloom if none exists
- Legacy `cascade.start` / `cascade.hop` / `cascade.end` listeners are no longer used by `ResonanceCascadeVisualization_Session117B`.
- `link.created` spawn in `ResonanceCascadeVisualization_Session117B` is now delayed by 0.5s and deduped with a 3.5s per-link cooldown to avoid instant spawn spikes.
- Added a normalized metrics phase layer in `NodeMetricEngine.js`:
  - emits `metric.phase.changed`
  - payload includes `metric`, `phase`, `previousPhase`, `value`, `nodeId`
  - phases are `low`, `normal`, `high`
  - existing threshold events like `metric:loadPressureHigh` remain for compatibility
- `WaveBurstRouter_v1.js` now consumes `metric.phase.changed` for node-level phase routing and keeps legacy threshold events only as compatibility/fallback inputs.
- `ResonanceRuptureVisualSystem_Session133.js` now consumes `metric.phase.changed` for `corruption`, `stability`, and `loadPressure` rupture pressure routing while keeping legacy threshold events as fallback.
- `LinkMicroImpulseAdapter_v1.js` now consumes `metric.phase.changed` as the preferred normalized link impulse signal, with legacy threshold events kept as fallback and deduped.
- `CascadeEventBridge_v1.js` now consumes `metric.phase.changed` as a normalized entry point for synergy/corruption high phases, while preserving the existing flowState write path.
- `MetricsRuntime_v1.js` now emits network-level `metric.phase.changed` for canonical live metrics (`synergy`, `harmony`, `stability`, `corruption`, `loadPressure`) alongside the legacy threshold events.
- `main.js` semantic event policy cleanup:
  - `metric.phase.changed` is now the canonical immediate path with no extra bus cooldown or aggregation
  - legacy `metric:*` threshold policies remain buffered as compatibility fallbacks
- Healing/recovery visual consumers are sensitive to raw metric ranges:
  - `HarmonicHealingVisualSystem_Session134`, `HealingParticleSystem_Session136`, and `HarmonicRecoveryVisualSystem_Session138` now clamp incoming harmony/synergy/corruption-style inputs locally
  - keep metric authority raw; normalize at the visual consumer boundary when the shader/spawn contract expects 0..1
- Temporary debug visibility pass:
  - healing/recovery/rupture visuals were boosted with high-contrast colors, larger sizes, and square/box silhouettes to make spawn behavior obvious in runtime
- Visual isolation switch added:
  - `window.__ATOMA_VISUAL_DEBUG__.setMode('rupture' | 'recovery' | 'healing' | 'all')`
  - each of the three visual consumers now early-outs unless its mode is active
- `ResonanceRuptureVisualSystem_Session133` scar visuals were converted to a dedicated particle-burst root spawned from the link midpoint.
- The scar root must stay attached to the active scene graph; if world lifecycle detaches it, `_ensureScarMeshesAttached()` reattaches the root during update.
- Link-born scar visuals are separate from rupture burst visuals, so the rupture burst can stay active while scar particles are tuned independently.
- `HealingParticleSystem_Session136` debug probe particles need a shader bypass path when they share the same `THREE.Points` warp as the main healing trail; otherwise they can be correctly spawned but still be visually invisible.
- `SynergyCascadeVisualizer.flowParticles` are the `THREE.Points` path and now share `LinkPointFXBase` for geometry / scene attachment / disposal, while `burstParticles` remain mesh-based for readability.
- `SynergyCascadeVisualizer.burstParticles` were also moved onto a `THREE.Points` path via `LinkPointFXBase`; the visual split is now point-based for both burst and flow, with burst kept secondary in scale and cadence.
- `LinkCorruptionSpreadAnimator` dust glyphs were reshaped into brighter chain-link markers so the corruption sweep reads more like a linked chain than a generic rune blob.
- `LinkRendererConduit` strand-tip sparks are now `THREE.Points` objects created through `LinkPointFXBase`, so their geometry, material, and cleanup follow the shared point-FX scaffold without changing the existing spark shader look.
- `HealingParticleSystem_Session136` healing trail particles now use `LinkPointFXBase` for shared geometry / material / attach / cleanup handling while preserving the existing shader look and debug probe behavior.
- `LinkBeadSystem` beads are now rendered as a shared `THREE.Points` cloud through `LinkPointFXBase` instead of individual meshes, with fewer beads per link, slower travel, and wider spacing so bead trails stay secondary to strand trails.
