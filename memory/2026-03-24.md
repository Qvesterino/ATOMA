## Confirmed Technical Findings

- Real runtime selection authority nie je `selectionCore`.
- Real selection authority je `NodeLinkingSystem.primaryNode` path:
  - `handleSingleClick()` -> `setPrimaryNode()` -> `_fireSelectCallbacks()`
  - `clearPrimaryNode()` -> `_fireDeselectCallbacks()`
- Pasivne audio callback API pre runtime selection je:
  - `NodeLinkingSystem.onNodeSelected(callback)`
  - `NodeLinkingSystem.onNodeDeselected(callback)`
- `NodeLinkingSystem.prototype.setSelectionCore = function() {};` je no-op, preto audio napojene len na `selectionCore` neobsluhuje realny click path.

## Safe State After Fixes

## Lessons

- Audio wiring sa nema tlacit do `main.js` link hot-path wrapperov.
- Pri ATOMA linking pipeline aj male defer/wrapper zasahy vedia rozbit link visual bootstrap alebo vyvolat freeze.
- Pre interaction audio preferovat pasivne callback API na skutocnej authority vrstve.

## LinkCorruptionParticleSystem Unlink Fade

- Root cause zamrznutych corruption particles po unlinku: `LinkRendererConduit` pocital s globalnym `corruptionParticleSystem.update(dt, time)`, ale `LinkCorruptionParticleSystem` tento update path realne nemal.
- Doterajsi `clearLinkParticles()` len odpojil link refs/index, ale bez globalneho `uTime` update a bez korektneho detach fade path ostavali shards vizualne "zamrznute" na poslednej pozicii.
- Fix smer:
  - pri unlinku sa particle "freeze-ne" do aktualnej world pozicie
  - vynuluje sa velocity/jitter
  - nastavi sa kratky post-unlink life window
  - globalny `update()` potom dobehne fade-out a vyradi particle z poolu

## LinkSemanticPictogramSystem Live-Link Sourcing

- Pictogram respawn bug po prvom unlinku nevyzeral ako renderer attach problem, ale ako stale-link cache problem v `LinkSemanticPictogramSystem_Enhanced`.
- Root cause:
  - `_getLinks()` vracal `_lastLinks` skor nez aktualne `linkingSystem.links`
  - `invalidateSpawnState()` cital linky cez `_getLinks()`, cim si vedel znovu zapisat ten isty stale cache stav
  - po prvom unlinku tak system mohol ostat "zamknuty" na starych link refs a nove linky uz nevidel
- Safe fix:
  - priorita live linkov bola presunuta pred `_lastLinks`
  - stale `_externalLinks` / `_lastLinks` sa pri cleari purguju pre zruseny link
  - orphan fade update path ostava bezana aj ked uz nie su live linky, aby system neskoncil predcasne

- Pictogram final-link bug root cause: clearLink() volal invalidateSpawnState() este pred realnym 	his.links removal v NodeLinkingSystem.removeLink(), cize posledny link sa znovu zapisoval do _lastLinks; fix je invalidateSpawnState(false) v unlink clear pathoch.
