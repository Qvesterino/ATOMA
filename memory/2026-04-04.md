# 2026-04-04

- NodeInspectOverlay_1_0 should not auto-dismiss itself on `link.created`; that behavior made inspection disappear after the first link and was too brittle for live linking workflows.
- LinkQualityCalculator now emits initial `link.<metric>.<tier>` events on first observation so link-tier visual systems can respond immediately when a new link is evaluated.
- `NodeInspectOverlay_1_0` prefers live `node.userData.metrics` over the last simulation snapshot when rendering metrics.
- `LinkQualityCalculator` must keep its tier payload `linkId` aligned with runtime `link.id` so consumers like HarmonicRecovery/HarmonicHealing can resolve the link.
- `LinkQualityCalculator` needs its internal numeric helper methods present (`_clamp01` in particular) because missing helpers silently break link-tier emission paths inside the metrics update loop.
- Harmonic healing and recovery visuals should use a single per-link cooldown gate rather than separate tier-specific cooldown maps; the simpler gate is easier to reason about and prevents spawn spam without extra policy layers.
- `HarmonicHealingVisualSystem_Session134` must resolve link endpoints via `sourceNode/source/from/nodeA` and `targetNode/target/to/nodeB`; hard-coding `source/target` blocks healing spawns on links whose live shape uses alternate endpoint fields.
- `HarmonicHealingVisualSystem_Session134` and `HarmonicRecoveryVisualSystem_Session138` both need explicit world-switch rebind/scene reattachment hooks so their pooled meshes and linked HealingParticleSystem stay on the active scene after a world rebuild.
- `PHASE5_CascadePropagationVisuals` now uses a 3-ring echo burst with a per-source 3 second cooldown so cascade propagation reads as a tighter repeating pulse instead of a single expanding ring.
- `PHASE5_CascadePropagationVisuals` now has a direct `link.harmony.low|mid|high` subscription path and resolves link midpoints from the active linking system; this is the primary visible trigger path because the old cascade-bridge-only path was too brittle in smoke tests.
- `TopologyBiasVisualizationLayer` now needs a stronger default visual pass: more visible bias vectors/flow fields plus fallback rendering from recent influence activity when the learning system has no active regions, otherwise it can read as dead even when the topology layer is alive.
- `SynergyCascadeVisualizer` now owns the visible echo ring pattern for `link.harmony.*`; this is the first functional move away from the old PHASE5 echo-ring presentation.
- `PHASE5_CascadePropagationVisuals` was demoted to a subtle single-ring support path to avoid duplicate echo bursts once Synergy became the visible owner.
- `TopologyBiasVisualizationLayer` was demoted to a snapshot publisher and no longer owns the visible topology showpiece.
- `SynergyCascadeVisualizer` now consumes `topology.bias.snapshot` and renders the visible topology feedback from link midpoint fallbacks when regions are not active.
