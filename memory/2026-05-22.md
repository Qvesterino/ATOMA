## 2026-05-22 — Synergy Shader Stack Invalid Program Hotfix
- Investigated the `WebGL: INVALID_OPERATION: useProgram: program not valid` spam reported on spawn-before-link runtime.

### Root cause
- The likely root issue is the legacy synergy shader stack boot path, not `renderer.render(...)` itself.
- Important discovery:
  - `index.html` already sets `window.ATOMA_DISABLE_SYNERGY_SHADER_STACK = true`
  - but `main.js` had broken flag wiring:
    - the disable flag was stored under `ATOMA_FLAGS.debug.disableSynergyShaderStacks`
    - the shader-stack boot gate read `ATOMA_FLAGS.visual.disableSynergyShaderStacks`
  - result: intended default shutdown was effectively ignored and the shader stack could still boot
- Additional cleanup signal:
  - the two synergy shader systems also had duplicate update wiring in `main.js`, which could amplify churn/noise when active

### Fix applied
- `main.js`
  - added a real `ATOMA_FLAGS.visual` branch
  - moved `disableSynergyShaderStacks` into the correct visual flag lane
  - made the release-safe default explicit:
    - synergy shader stacks stay disabled unless intentionally re-enabled
  - removed duplicate update registration for:
    - `synergyBonusFXLayer`
    - `synergyResonanceShaderPack`

### Verification
- `node --check main.js`
- runtime smoke on `http://127.0.0.1:5173/`
  - confirmed:
    - `ATOMA_FLAGS.visual.disableSynergyShaderStacks === true`
    - `window.ATOMA_DISABLE_SYNERGY_SHADER_STACK === true`
    - `window.game.synergyBonusFXLayer === null/falsey`
    - `window.game.synergyResonanceShaderPack === null/falsey`
    - no synergy shader init logs during boot
    - no `INVALID_OPERATION / useProgram / program not valid` logs in the smoke run

## 2026-05-22 — Bugfix: Global stability 0.22 with zero links

### Problem
- User reported: global stability shows `0.22` even though no links were created.
- Expected: `0.00` when the network is empty.

### Root cause
- `MetricsRuntime_v1._publishLiveMetrics()` uses exponential smoothing (`_dampingFactor = 0.04`) to decay metric values toward raw targets.
- When all links are removed (or the game starts without links), `_resolveRawNetworkMetricsSnapshot()` correctly returns zeros with `source: 'empty'`.
- However, the smoothed accumulator (`_smoothedMetrics.networkStress`) decays very slowly — from `0.22` to `0` takes ~7–8 seconds at 10Hz.
- The HUD reads from `window.__ATOMA_LIVE_METRICS__`, which is fed by the smoothed accumulator, so it displays the stale decaying value.

### Fix
1. **MetricsRuntime_v1.js** — `_publishLiveMetrics()`
   - Added fast-path: if `result.linkCount <= 0` or `result.source === 'empty'`, immediately reset `_smoothedMetrics` to all zeros and publish zeros without smoothing.
   - This guarantees the HUD snaps to `0.00` the moment the network becomes empty.

2. **HUD/CoreMetricsOverlay.js** — `_getCanonicalGlobalMetrics()`
   - Added safety net: if `linkCount <= 0`, force all metrics to `0` regardless of what `liveMetrics` or `rawMetrics` contain.
   - Prevents any future leak of stale smoothed values into the HUD pipeline.

### Files touched
- `MetricsRuntime_v1.js`
- `HUD/CoreMetricsOverlay.js`

### Verification
- `node --check MetricsRuntime_v1.js`
- `node --check HUD/CoreMetricsOverlay.js`
- `git diff --check -- MetricsRuntime_v1.js HUD/CoreMetricsOverlay.js`

### Lesson
- Exponential smoothing is good for visual softness during normal play, but it must have an immediate reset path for edge states (empty network, victory, collapse). Otherwise stale values create false player feedback.
