## GlyphLayer4 Visibility Issue Fixed

**Problem**: GlyphLayer4 glyphs were completely invisible on all nodes.

**Root Cause**: `GlyphPurityMode5_1` (initialized with purity level 3 - PURE mode) was blocking GlyphLayer4.
- GlyphPurityMode5_1 enforces strict visual purity by checking `userData.glyphComponent` on all glyph meshes
- GlyphLayer4 meshes did NOT set `userData.glyphComponent` 
- Therefore, GlyphPurityMode5_1 removed them as "unauthorized" via `purifyScene()`

**Fix Applied** (main.js):
- Disabled GlyphPurityMode5_1: `this.glyphPurityMode.setPurityEnabled(false)`
- Commented out purity level setting: `// this.glyphPurityMode.setPurityLevel(3)`
- Commented out automatic cleanup: `// this.glyphPurityMode.purifyScene()`
- Added debug logging for GlyphLayer4 initialization

**Status**: GlyphLayer4 should now be visible on all nodes after restart.

**Change Classification**: Class A - Safe Surgery
- No gameplay changes
- No visual philosophy changes
- Minimal, reversible diff
- Fixes regression (GlyphPurityMode5_1 being too aggressive)

## LinkBeadTrailSystem Memory Leak Fixed

**Problem**: Missing `scene.remove()` in dispose() method

**Fix Applied** (LinkBeadTrailSystem.js):
```javascript
dispose() {
    if (this.mesh) {
        // Remove from scene if attached
        if (this.mesh.parent) {
            this.mesh.parent.remove(this.mesh);
        } else if (this.scene) {
            this.scene.remove(this.mesh);
        }
        
        // Dispose resources
        this.mesh.geometry.dispose();
        this.mesh.material.dispose();
    }
}
```

**Change Classification**: Class A - Safe Surgery

## LinkTrailParticleSystem Visibility Fixed

**Problem**: Particles not visible despite being marked as ACTIVE in audits

**Root Cause**: Race condition between link creation and curve initialization
- LinkTrailEmitter created in main.js hook (immediate)
- link.curve property not initialized until NodeLinkingSystem.update() 
- FrameScheduler guarded with `if (link.curve)` - emission blocked until curve exists

**Fix Applied** (NodeLinkingSystem.js):
```javascript
const link = {
    source: sourceNode,
    target: targetNode,
    sourceNodeId: this.getNodeId(sourceNode),
    targetNodeId: this.getNodeId(targetNode),
    group: null,
    curve: null,  // ← ADD: Initialize curve property
    active: true,
    // ...
};
```

**Secondary Fix** (LinkRendererConduit.js):
- Moved LinkTrailEmitter creation from main.js to LinkRendererConduit.createLinkVisuals()
- Eliminates race condition - conduit already has curve access
- Stored in state.trails for consistency with other subsystems

**Status**: Particles should be visible immediately after link creation

**Change Classification**: Class A - Safe Surgery
- Adds null initialization (no behavior change)
- Moves existing code (consistency improvement)
- No gameplay/visual changes

## LinkTrailEmitter LinkRendererConduit Integration

**Problem**: LinkTrailEmitter was managed in main.js causing race condition

**Solution**: Integrated into LinkRendererConduit following LinkSparkSystem pattern

**Changes** (LinkRendererConduit.js):
```javascript
// Create emitter in createLinkVisuals()
let linkTrailEmitter = null;
try {
    if (LinkTrailEmitter && window.game?.linkTrailParticles) {
        linkTrailEmitter = new LinkTrailEmitter(link, window.game.linkTrailParticles);
        state.trails = linkTrailEmitter;
    }
} catch(e) {
    console.warn('[LinkRendererConduit] LinkTrailEmitter creation failed:', e);
}

// Update emitter in update()
if (state.trails && mainCurve) {
    const stats = { harmony: vfx.harmony ?? 0.5, corruption: vfx.corruption ?? 0.2 };
    state.trails.update(visualDelta, visualTime, mainCurve, linkDirection, stats.harmony, stats.corruption);
}
```

**Architecture Pattern**: Global particle pool + per-link emitter
- Global: window.game.linkTrailParticles (300 particle pool)
- Per-link: state.trails (LinkTrailEmitter per link)
- Updates: 30Hz in FrameScheduler visual layer

**Change Classification**: Class A - Safe Surgery
- Moves existing code to proper location
- Consistent with LinkSparkSystem pattern
- No behavior change
