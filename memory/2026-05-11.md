## Render Blackout Safeguard - PostProcessing Layer Recovery

- Investigated intermittent "world goes dark / only emissive bloom candidates remain" state on Quantum Island under certain camera angles and movements.
- Highest-confidence root cause was selective bloom camera layer masking in the post-processing path:
  - `LuminosityBloomPipeline` temporarily switches `camera.layers` to the bloom layer for `bloom.selectiveSource`
  - render loop in `main.js` previously called `op.after()` without `try/finally`
  - if a render operation aborted mid-pass, camera layer restoration could be skipped, leaving the camera effectively stuck on bloom-only visibility
- Applied runtime safeguard:
  - `BloomPass.restorePendingCameraLayerMask()`
  - `PostProcessingPipeline.restoreRenderState()`
  - `LuminosityBloomPipeline.restoreRenderState()`
  - `main.js` now restores pending camera-layer state at the start of each frame, wraps post-processing ops in `try/finally`, and restores again in the render catch path
- Scope of fix was surgical: no gameplay changes, only render-state hardening.
- Quantum Island rušivé ružové vertikálne 2D sheets boli identifikované ako veľmi pravdepodobný `SafeQuantumIllusionsPack1.generateAfterPaths()` artifact (`3` ribbons + `3` ghosts + `1` highlight = `7` planov v jednej zostave, VEIL_BREACH palette). Pre demo sú `afterPaths` defaultne disabled, runtime pri disabled stave prune-ne existujúce `afterPaths` entries a `quantumIllusions.getStatus()` teraz vracia truth pre `afterPaths.enabled` a active count.
