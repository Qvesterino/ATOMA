## Network Time Score Gameplay — COMPLETED

### Architecture Plan: `plans/NETWORK_TIME_SCORE_GAMEPLAY.md`

### Concept
Network Time is now the **gameplay score**:
- Counts FORWARD at 5 units/sec (pressure)
- When `global.synergy >= 0.82` sustained for **7 seconds** → counts DOWN at 3 units/sec (reward)
- If synergy drops → resumes FORWARD
- **Win condition**: Network Time reaches 0 → game won
- No game over — player can try forever

### Files Modified:

#### `VisualNetworkTimeElasticity_v1.js` — Major refactor (v1 → v2)
- Was: visual-only time rewind effect (zero gameplay impact)
- Now: **gameplay score authority** + visual time elasticity
- Added: `networkTimeCounter`, `SCORE_DIRECTION` enum (FORWARD/REWIND/WON)
- Added: sustain timer (7s), forward speed (5/sec), rewind speed (3/sec)
- Added: gameplay events (`score:forward`, `score:rewinding`, `score:won`)
- Preserved: visual time elasticity as sub-feature (animation rewind at 40% speed)
- New exports: `SCORE_DIRECTION`, `getNetworkTime()`, `getDirection()`, `isWon()`, `getScoreState()`

#### `HUD/CoreMetricsHUD.js` — Medium refactor

### Key Design Decisions:
- Rewind speed (3/sec) is slower than forward (5/sec) — intentional difficulty
- Synergy threshold 0.82 aligned with MetricsRuntime `global.synergy.high`
- Win = freeze + victory overlay (Tier4 notification + semantic event)
- No game over — infinite retries
- Start at 0 — player must first accumulate time before rewinding
